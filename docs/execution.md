# 执行规则

## 生命周期

技能会话由 idle 开始。参数、组件与工厂校验完成后取得资源，再调用 start。重复调用同一会话的 start 不会重复下发。

正常动作 running 后可以 succeeded 或 failed；请求取消/超时后进入 canceling，继续轮询直到组件确认终止，才返回 canceled/timed_out 并释放资源。

组件异常或无法确定状态时进入 faulted，保留资源。任务级停止超过 stop_timeout_ms 会锁定运行时并报告 STOP_UNCONFIRMED。

| 事件 | 行为 |
|---|---|
| 缺参数、错误绑定、未知实现 | 下发前拒绝 |
| 资源占用冲突 | 拒绝，不排队，不自动重试 |
| 普通失败且设备确认静止 | 释放资源，任务失败 |
| 请求取消 | 发停止请求，继续等待确认 |
| 技能超时 | 使用相同的停止确认流程 |
| 连接/组件异常 | 最佳努力停止，状态锁定，保留资源 |
| 停止确认超时 | 任务以故障结束，继续阻止新任务 |

## ROS 与行为树

`ExecuteTask` 接受已安装任务模板。v0 为 pick_place 固定模板。整个任务、单个技能和停止确认有各自的 deadline，使用 steady_clock，避免系统时钟跳变。

RuntimeNode 使用单线程 executor，所有核心对象由同一线程访问。行为树节点仅启动技能和读取状态；timer 负责推进会话。即使节点 halt，会话仍由 Engine 持有，以等待取消确认。后续添加并行树或多线程 executor 前需重新验证同步和资源管理。

ROS Action 的“接受取消”和最终 canceled 是两个阶段。仅在收到停止确认后报告正常取消。停止状态未知时报告 faulted/abort，不伪装成已安全取消。

ROS goal UUID 是任务实例身份。v0 没有跨重连/跨重启的幂等请求存储，重发新目标会产生新任务。任务执行中拒绝第二个目标。实际设备接入前应补充持久执行账本、重连状态对账，禁止网络超时后盲目重试。

6A 增加本进程有界执行记录和只读查询，见 [执行记录与状态查询](execution_records.md)。按 goal UUID 查询实际结果，不改变停止路径；查询不到记录也不能推断任务没有执行。

## 状态与验证

定位失败会删除旧观测。抓取物体和放置目标都必须具有有效、坐标系明确且未过期的位姿；开始移动即消费并删除该观测。技能先验收 `ArmMotion` 到位反馈，再执行 `Gripper`，并根据夹持检测更新示例世界状态，不把“命令已接受”当作完成。这仍是软件示例，并不代表已有真实视觉/夹持验证。

技能条件文本是文档元数据。当前强制条件写在具体实现中；注册新实现的开发者必须实现相同语义，注册表不会自动证明正确性。

## v0.3 验收契约

- 位姿必须为有限数值，四元数必须接近单位长度；不静默归一化无效输入。
- `ArmMotion`/`Gripper` 接口版本为 2，反馈带单调时钟时间戳、有效性和停止状态。收到终态结果仍须等待新鲜的停止测量，过期/缺失/仍在运动的反馈不能释放资源。
- 手臂位置误差与四元数角距离分别受容差约束；两个符号相反的等价四元数可通过验收。
- 取消状态一旦设置，技能实例永久禁止启动下一子动作；运行时先处理任务取消/超时，再推进技能。
- 夹持/释放与取消同时完成时，根据有效反馈对账附着状态；取消不能抹掉已经发生的夹持效果。
- 释放只生成 `placement_candidates`，不把目标位置写为观测事实。真实物体是否在托盘上需感知组件再验证。

## 6B 证据验收

定位证据必须具有来源、质量、合成标记和位姿语义；当前运动技能只接受 motion_target。抓稳/放置验证要求动作后的新样本和时间窗口，通过后保存证据来源。开始后续操作使旧验证失效，步骤历史仍保留已验收证据。示例证明合成数据路径，真实物理条件需替换观察组件；详见 [感知证据与结果验证](perception_verification.md)。

## 停机边界

进程退出仅能发出最佳努力停止请求，无法保证设备已停。运行时、网络和供电异常时的独立保护应在硬件/控制系统处理。v0 不接硬件。将 mock 替换成真实驱动之前，必须补齐设备级停止确认、看门狗和人工恢复流程。
