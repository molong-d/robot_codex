# 扩展指南

## 新增组件实现

1. 确定职责：感知、运动规划、动作策略、控制或硬件适配。
2. 实现对应的类型化契约。示例见 `ObjectLocator`、`Manipulator`。
3. 声明接口类型、接口版本和物理资源 ID。两个适配器控制同一机械臂时必须使用相同资源 ID。
4. 在启动组合处注册实例；将技能使用的角色绑定到该实例。
5. 验证输入、输出单位/坐标系/时序及取消行为；增加契约测试。

v0 的 `mock_arm` 与 `slow_mock_arm` 展示配置替换。注册表支持显式工厂和实例注册，没有实现动态库热加载。

## 新增技能

1. 写明目标语义、输入、组件依赖、资源、前置/维持/成功条件。
2. 用 `Skills::define` 注册定义，使用 `Skills::implement` 注册一个或多个实现。
3. 实现非阻塞 start/tick/cancel。构造函数只绑定依赖，不发送硬件命令。
4. 执行前验证条件，执行中检查维持条件，以观测反馈验证成功。
5. 明确终态意味着本技能指令已停止或完成。未知物理状态返回 faulted。
6. 更新任务模板和 ROS 入口的参数映射，再验证成功、失败、取消路径。

当前 BT 适配节点只提供 object/target 示例端口。新增技能如需位姿、力、轨迹等参数，应扩展明确的 C++/ROS 类型和 BT 端口，不能假定 v0 通用支持所有参数。

同一技能可有传统实现与学习策略实现。技能定义共享时，输入语义、成功条件和执行约束必须一致；如果两种实现对外承诺不同，应拆分定义或版本。每种实现通过 `Dependencies` 独立声明组件需求和独占资源角色，因此 VLA 实现不必假装使用传统 6D 感知组件。

## 执行许可门

`ExecutionGate` 是组件契约，位于技能会话取得独占资源与调用技能 `start` 之间。会产生物理动作的技能实现把它声明为 `execution_gate_role`；拒绝时以明确错误码结束，既不会占用机械臂资源，也不会调用驱动。

- mock 使用 `mock_motion_permitted` 演示此边界。它不能替代真正的急停、看门狗或功能安全系统。
- 真实适配器可将许可判断连接到 E-stop 状态、围栏、手自动模式、控制器激活状态和人工授权，但需要为每一项定义刷新率、失联策略和错误码。
- 许可仅在技能开始前检查。执行期间的独立安全停止必须由控制器/硬件链路处理；运行时仍等待底层的停止确认。

## 新增硬件

- 优先复用已有厂商 ROS 驱动与 ros2_control hardware plugin；不直接修改技能业务逻辑。
- 明确机器人模型、关节顺序、控制模式、坐标系、单位、限制和标定。
- `Manipulator` 只是 mock 操作契约。真实设备建议分开轨迹执行、夹爪、状态和控制模式接口，再由技能组合。
- 首次实机接入前实现独立停止/看门狗、真实反馈验证和故障恢复流程。

## 未来模型扩展位置

| 模型输出 | 接入位置 | 后续需确认的契约 |
|---|---|---|
| 技能级步骤/子目标 | 任务规划适配 | 技能白名单、输入约束、计划版本、状态快照 |
| 物体/语义/位姿 | 感知组件 | 坐标、时效、精度/不确定性、相机标定 |
| 连续动作或动作片段 | 动作策略组件 | 观测同步、动作空间、时序、过期处理与中断 |

不绑定 π0.5 或任何特定提供商。不把“任意模型返回 JSON”定义为模型通用接口。将来选定一个真实模型和设备后，用第二个实现验证抽象是否足够。

模型规划不得直接绕过任务运行时调用驱动；动作策略可绕过传统几何规划，但仍通过本地控制权仲裁与执行约束。模型超时后不能盲目重发动作。

## 数据与评测

v0 只提供 ROS 日志与测试结果。未来接入 rosbag2/执行事件记录时，分别记录模型建议动作、实际下发动作、观测、人工干预和结果，保留时钟、标定与模型版本。
